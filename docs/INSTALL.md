## Архитектура

```
        ┌──────────────┐
        │     Mac      │  10.9.0.3
        └──────┬───────┘
               │ WireGuard
        ┌──────▼───────┐
        │    Панель    │  10.9.0.2   ← хаб, единственный ListenPort
        │  Next.js +   │
        │  PostgreSQL  │
        └───┬──────┬───┘
            │      │  WireGuard
     ┌──────▼─┐  ┌─▼──────┐
     │ VPN #1 │  │ VPN #2 │  10.9.0.1 / 10.9.0.5
     │amnezia-│  │amnezia-│
     │  api   │  │  api   │
     └────────┘  └────────┘
```

Панель — **хаб**: у неё один открытый UDP-порт, все остальные дозваниваются к ней.
Спицы друг друга не видят, и это нормально: им незачем.

Ключевые свойства, из которых вытекает почти всё остальное:

- Панель ходит к API по `http://${ip}:${port}` — **схема захардкожена, HTTPS не поддерживается**.
  Поэтому трафик до API обязан идти по заведомо приватному каналу.
- Панель одна на все VPN-серверы. Вторую поднимать не нужно.
- Порт API (`4001`) не должен смотреть в интернет ни при каких условиях.

## Что понадобится

| | |
|---|---|
| VPN-сервер | Amnezia уже установлена и работает |
| Сервер панели | 2 ГБ RAM (см. ниже), Docker, Debian/Ubuntu |
| Домен | **не нужен** — панель админская, её видите только вы |

**Про память.** `next build` внутри Docker жрёт до ~1.07 ГБ. На гигабайтном сервере
сборка падает по OOM в середине. Либо берите 2 ГБ, либо добавьте своп:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

Своп стоит оставить навсегда — Next.js в рантайме тоже иногда всплёскивает.

## Шаг 1. amnezia-api на VPN-сервере

### 1.1. Разведка

Прежде чем что-то ставить, соберите три числа — они у каждой машины свои,
и значения с соседнего сервера **не подойдут**:

```bash
# GID владельца docker-сокета
stat -c '%g' /var/run/docker.sock

# Версия Docker API
docker version --format '{{.Server.APIVersion}}'

# Какие протоколы Amnezia реально установлены
docker ps --format '{{.Names}}' | grep amnezia
```

Заодно проверьте, что подсеть `10.9.0.0/24` и порт `51820/udp` свободны:

```bash
ip -brief addr
ss -ulnp | grep -v 127.0
```

### 1.2. Установка

```bash
cd ~   # запомните каталог — он важен, см. ниже
git clone https://github.com/Ximelay/amnezia-api
cd amnezia-api
```

### 1.3. Конфигурация

Создайте `.env` **в том же каталоге, где лежит `docker-compose.yml`**:

```bash
cat >> .env <<EOF
API_KEY=$(openssl rand -hex 32)
DOCKER_GID=$(stat -c '%g' /var/run/docker.sock)
DOCKER_API_VERSION=$(docker version --format '{{.Server.APIVersion}}')
PROTOCOLS_ENABLED=amneziawg2
EOF
```

> **Каталог `.env` критичен.** Docker Compose берёт `.env` для подстановки `${...}`
> из каталога проекта. Если положить его в другое место, `group_add: ["${DOCKER_GID:-999}"]`
> молча возьмёт дефолт `999`, и API не сможет читать docker-сокет.
> `env_file:` тут не помогает — он передаёт переменные **внутрь** контейнера,
> а не в сам compose-файл.

`PROTOCOLS_ENABLED` перечисляйте строго по выводу разведки. Дефолт включает три
протокола, и если контейнера нет — API отдаёт `503` без внятного объяснения.

### 1.4. Запуск

```bash
docker compose up -d --build
```

Пока оставьте порт на `127.0.0.1` — привяжем его к WireGuard после шага 2.

### 1.5. Проверка

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4001/clients
```

Ждём **`401`** — API отвечает и требует ключ. Это успех.
`000` или `500` — смотрите [разбор ошибок](#разбор-ошибок).

## Шаг 2. WireGuard между серверами

Схема адресов — зафиксируйте её сразу, иначе на третьей машине начнётся путаница:

| Адрес | Кто |
|---|---|
| `10.9.0.1` | VPN-сервер #1 |
| `10.9.0.2` | панель (хаб) |
| `10.9.0.3` | ноутбук |
| `10.9.0.4` | телефон |
| `10.9.0.5` | VPN-сервер #2 |

### 2.1. Ключи — на каждой машине

```bash
apt install -y wireguard
umask 077
wg genkey | tee /etc/wireguard/private.key | wg pubkey > /etc/wireguard/public.key
cat /etc/wireguard/public.key
```

Публичные ключи нужны крест-накрест. Приватные с машины не уезжают.

### 2.2. Панель — хаб

`/etc/wireguard/wg0.conf`:

```ini
[Interface]
Address = 10.9.0.2/24
ListenPort = 51820
PrivateKey = <приватный ключ панели>

[Peer]                          # VPN-сервер #1
PublicKey = <публичный ключ VPN#1>
AllowedIPs = 10.9.0.1/32

[Peer]                          # ноутбук
PublicKey = <публичный ключ ноутбука>
AllowedIPs = 10.9.0.3/32
```

> **У пиров на стороне хаба нет `Endpoint` и нет `PersistentKeepalive` — так и надо.**
> `Endpoint` нужен только инициатору. Хаб узнаёт адрес пира из первого валидного
> хендшейка и запоминает сам; это же даёт роуминг — если у спицы сменится IP,
> хаб подхватит новый без правок. Слать keepalive хабу некуда: до хендшейка
> он не знает, куда.

### 2.3. Спицы

`/etc/wireguard/wg0.conf` на VPN-сервере #1:

```ini
[Interface]
Address = 10.9.0.1/24
PrivateKey = <приватный ключ VPN#1>

[Peer]
PublicKey = <публичный ключ панели>
Endpoint = <публичный IP панели>:51820
AllowedIPs = 10.9.0.2/32
PersistentKeepalive = 25
```

На ноутбуке (приложение WireGuard → Add empty tunnel):

```ini
[Interface]
PrivateKey = <генерируется приложением>
Address = 10.9.0.3/32

[Peer]
PublicKey = <публичный ключ панели>
Endpoint = <публичный IP панели>:51820
AllowedIPs = 10.9.0.2/32
PersistentKeepalive = 25
```

> **`AllowedIPs` — никогда `0.0.0.0/0` на клиенте.**
> Это поле правит таблицу маршрутов. С `0.0.0.0/0` весь трафик машины, включая
> вашу SSH-сессию, уйдёт в тоннель. На ноутбуке `/32` заодно даёт сосуществование
> с включённым AmneziaVPN: конкретный маршрут выигрывает у дефолтного.

`AllowedIPs` разных пиров **не должны пересекаться** — иначе трафик пойдёт не туда,
и ломаться это будет крайне невнятно.

### 2.4. Поднять

```bash
systemctl enable --now wg-quick@wg0
```

На панели, если включён ufw: `ufw allow 51820/udp`.
Проверьте ещё **облачный фаервол хостера** — входящий UDP там часто закрыт
по умолчанию, и на самой машине это никак не диагностируется.

Добавление пира на живой хаб — без разрыва существующих:

```bash
wg syncconf wg0 <(wg-quick strip wg0)
```

### 2.5. Проверка

```bash
wg show          # у каждого пира должен появиться latest handshake
ping -c3 10.9.0.1
```

### 2.6. Привязать API к тоннелю

Теперь на VPN-сервере в `docker-compose.yml`:

```yaml
ports:
    - "127.0.0.1:4001:4001"
    - "10.9.0.1:4001:4001"
restart: unless-stopped
```

Оба адреса, а не вместо: loopback нужен для локальной отладки.
`restart: unless-stopped` — на случай, если Docker стартует раньше `wg0`:
привязка к `10.9.0.1` провалится, и без политики перезапуска контейнер останется лежать.

```bash
docker compose up -d --force-recreate
```

> **`--force-recreate` обязателен.** При неизменном образе обычный `up -d` оставит
> контейнер как есть, и порт не поменяется. Симптом — `ss` показывает старый биндинг,
> хотя в файле новый.

Проверка:

```bash
ss -tlnp | grep 4001     # ждём две строки, одна с 10.9.0.1
```

Закрывать `4001` через ufw бесполезно: Docker публикует порты в обход его цепочек.
Правило вы напишете, оно применится, порт останется открыт. Защищает только явный
адрес в биндинге.

## Шаг 3. Панель

### 3.1. Код

```bash
cd /opt
git clone <ваш форк> amnezia-panel
cd amnezia-panel
```

Именно **свой** форк — правки (reissueConfig, привязка Telegram по deep link,
напоминания за день) живут только в нём.

### 3.2. Правки до первого запуска

**`panel/docker-compose.yaml`** — закрыть панель от интернета:

```yaml
ports:
    - "127.0.0.1:8443:8443"
```

**`panel/nginx.conf`** — две правки, обе обязательные:

```nginx
http {
    # ...
    client_body_timeout 60s;      # было 0
    proxy_request_buffering on;   # было off
}

server {
    listen 0.0.0.0:8443 ssl backlog=65535;
    http2 on;                     # новое
    # ...

    location /_next/static/ {     # новое, выше location /
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
}
```

> **`client_body_timeout 0` в nginx — это не «без ограничения», а таймер,
> который истекает немедленно.** По HTTP/1.1 небольшое тело запроса приходит тем же
> пакетом, что и заголовки, ждать нечего — и баг не проявляется. Под HTTP/2 тело идёт
> отдельным DATA-фреймом, nginx вынужден его дождаться, таймер срабатывает и рвёт
> соединение. Симптом: все GET проходят, **любой POST падает**, включая вход в панель.
> В HAR это выглядит как `status: 0` с пустым `httpVersion`, в логах приложения —
> `Error: aborted / ECONNRESET`.

`http2 on` даёт заметный выигрыш при доступе через SSH-туннель: страница тянет
пару десятков файлов, и по HTTP/1.1 каждое из шести параллельных соединений
стоит отдельного SSH-канала и TLS-хендшейка.

**`scripts/setup-root.sh`, `reset-root.sh`, `time2pay.sh`** — все трое берут адрес
через `hostname -I`, то есть внешний IP, где после смены биндинга уже никто не слушает:

```bash
sed -i 's|https://\$MACHINE_IP:8443|https://127.0.0.1:8443|' \
    scripts/setup-root.sh scripts/reset-root.sh scripts/time2pay.sh
```

### 3.3. Запуск

```bash
apt update && curl -fsSL https://get.docker.com | sh
apt install -y git openssl
bash scripts/deploy.sh
```

Скрипт спросит имя сервиса и доступы к БД, сгенерирует секреты, выпустит
самоподписанный сертификат, поднимет контейнеры, пропишет два крона
(бэкап раз в 3 дня, `time2pay` в 10:30) и заведёт systemd-юнит автостарта.

### 3.4. Дописать в `.env`

```
NEXTAUTH_URL="https://127.0.0.1:8443"
```

Без неё NextAuth угадывает адрес из заголовков и за прокси ставит куку без флага
`Secure`. Симптом: логин проходит, но выкидывает обратно на форму.

Адрес должен **посимвольно** совпадать с тем, что в адресной строке. Выберите один
канонический способ доступа и держитесь его.

```bash
cd panel && docker compose up -d --force-recreate
```

### 3.5. Сохранить `ENCRYPTION_KEY`

```bash
grep ENCRYPTION_KEY panel/.env
```

**Это единственное, что нельзя потерять.** Им зашифрованы `vpnKey` и `apiKey` в базе.
Потеряете — база превратится в мусор, все конфиги придётся перевыпускать.
В менеджер паролей, сразу.

## Шаг 4. Первый вход

```bash
bash scripts/setup-root.sh
```

Создаёт учётку **`root` / `rootadmin`** — пароль захардкожен в
`src/app/api/auth/setup-root/route.ts`.

> **`reset-root.sh` не сбрасывает пароль, а переименовывает учётку** в
> `root_reseted` (пароль тот же, `rootadmin`). Скрипт пишет это в ответе, но
> легко пропустить. Если после сброса не пускает под `root` — вы просто ищете
> несуществующего пользователя.

Дальше по порядку:

1. **Сменить пароль.** У свежей учётки `isFirstLogin = true`, панель попросит сама.
2. **Добавить сервер:** `ip: 10.9.0.1`, `port: 4001`, ключ из `.env` API.
3. **Открыть Payment Settings и сохранить хотя бы раз.** Даже если платная часть
   не нужна — сохраните с нулями. Без строки в этой таблице `time2pay` возвращает
   `400` и молча ничего не рассылает.
4. **Проверить крон:** `bash scripts/time2pay.sh` → ждём
   `Notifications were sent successfully` или `Clients not found`, но не `400`.
5. **Завести крон очистки ключей** (если бот раздаёт конфиги в Telegram):

   ```bash
   crontab -e
   # 0 * * * * /root/amnezia-panel/scripts/telegram-cleanup.sh >> /var/log/tg-cleanup.log 2>&1
   ```

   Он удаляет из чатов клиентов сообщения с ключами старше
   `TELEGRAM_KEY_TTL_MINUTES` (по умолчанию 12 часов). **Раз в час — это не
   перестраховка:** Telegram не даёт боту удалить собственное сообщение старше
   48 часов, и пропущенное окно оставляет ключ в переписке навсегда. Чтобы
   выключить очистку, поставьте `TELEGRAM_KEY_TTL_MINUTES="0"`.

Проверить, какая учётка реально в базе:

```bash
docker exec db-amnezia-panel sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select id, login, role, \"isFirstLogin\" from \"Admins\";"'
```

## Шаг 5. Доступ к панели

### Вариант A. SSH-туннель

`~/.ssh/config` на ноутбуке:

```
Host panel
    HostName <IP панели>
    User root
    LocalForward 8443 127.0.0.1:8443
    Compression yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
    ControlMaster auto
    ControlPath ~/.ssh/cm-%r@%h:%p
    ControlPersist 10m
```

```bash
ssh -N panel
```

`ServerAliveInterval` не косметика: без него туннель тихо умирает после простоя,
и вы получаете зависшую вкладку вместо понятной ошибки.

Чтобы поднимался сам — `brew install autossh` и LaunchAgent с
`autossh -M 0 -N panel`. Требует входа по ключу: при парольной аутентификации
агент молча падает, спросить пароль ему негде.

### Вариант B. WireGuard (удобнее, работает с телефона)

Ноутбук уже пир из шага 2.3 — просто откройте `https://10.9.0.2:8443`.

Панель при этом должна слушать адрес в тоннеле. В `panel/docker-compose.yaml`:

```yaml
ports:
    - "127.0.0.1:8443:8443"
    - "10.9.0.2:8443:8443"
```

Loopback оставляем: локальные скрипты ходят именно на него.

И не забудьте согласовать `NEXTAUTH_URL` с выбранным адресом.

### Про адрес

Заходите на `https://127.0.0.1:8443`, а не на `https://localhost:8443`.

nginx отдаёт `Strict-Transport-Security: max-age=63072000`. Заголовок привязан
к имени хоста, и если это имя — `localhost`, браузер на два года запомнит, что
на `localhost` можно только по HTTPS. Ваш локальный `http://localhost:3000` после
этого может начать принудительно редиректиться. `127.0.0.1` — отдельный хост,
`localhost` не заденет.

Если уже наступили: `chrome://net-internals/#hsts` → Delete domain security policies.

## Шаг 6. Второй VPN-сервер

Панель уже умеет несколько серверов, вторую поднимать не нужно. Повторить надо
только API и связь.

1. **amnezia-api** — весь [шаг 1](#шаг-1-amnezia-api-на-vpn-сервере) заново.
   Три числа из разведки берутся с **этой** машины, значения с первого сервера
   не подойдут.

2. **WireGuard** — проще, чем в первый раз: у панели уже есть `ListenPort`,
   новый сервер просто дозванивается. Открывать порты на нём не нужно.

   На новом сервере — конфиг спицы из [2.3](#23-спицы) с `Address = 10.9.0.5/24`.

   На панели дописать блок:

   ```ini
   [Peer]
   PublicKey = <публичный ключ нового сервера>
   AllowedIPs = 10.9.0.5/32
   ```

   и применить без разрыва: `wg syncconf wg0 <(wg-quick strip wg0)`.

3. **Привязать API** к `10.9.0.5:4001` — как в [2.6](#26-привязать-api-к-тоннелю).

4. **Добавить в панели:** `ip: 10.9.0.5`, `port: 4001`, свой собственный ключ.

Проверка с сервера панели — **изнутри контейнера**, а не с хоста:

```bash
docker exec app-amnezia-panel wget -O- -T 5 http://10.9.0.5:4001/clients
```

Ждём `HTTP/1.1 401 Unauthorized`.

## Разбор ошибок

### Диагностика по слоям

Прежде чем чинить, определите слой. Три команды разводят все случаи:

```bash
# 1. Тоннель
wg show                                    # есть ли свежий latest handshake

# 2. Сеть до API — ИЗНУТРИ контейнера панели, не с хоста
docker exec app-amnezia-panel wget -O- -T 5 http://10.9.0.X:4001/clients

# 3. Внутренности API
docker logs --tail 30 amnezia-api
```

Ключ к чтению пункта 2:

| Что видим | Что это значит |
|---|---|
| `401 Unauthorized` | всё хорошо, API отвечает |
| `Connection refused` | **пакет дошёл**, но порт закрыт — тоннель цел, не слушает API |
| `can't connect` / таймаут | пакет не дошёл — проблема в тоннеле или маршрутах |
| `500` | ключ принят, API упал внутри — смотрите пункт 3 |

Разница между «refused» и «таймаутом» экономит массу времени: отказ в соединении
**доказывает**, что сеть работает.

---

### `permission denied ... /var/run/docker.sock`

API не может читать docker-сокет.

```bash
stat -c '%g' /var/run/docker.sock     # авторитетное значение
docker exec amnezia-api id            # с какими группами реально работает процесс
```

В `groups=` должен быть номер из первой команды. Если там `999` — это дефолт из
`group_add: ["${DOCKER_GID:-999}"]`, то есть переменная не подставилась.

Причины по убыванию вероятности:

1. **`.env` лежит не в каталоге проекта.** Compose ищет его рядом с compose-файлом.
2. В compose-файле вообще нет секции `group_add` — добавьте:
   ```yaml
   group_add:
       - "${DOCKER_GID}"
   ```
3. Не сделан `--force-recreate`.

Проверка подстановки **до** пересоздания:

```bash
docker compose config | grep -A2 group_add    # должно быть реальное число
```

```bash
echo "DOCKER_API_VERSION=$(docker version --format '{{.Server.APIVersion}}')" >> .env
docker compose up -d --force-recreate
```

### Панель: `Amnezia API request failed: fetch failed`

Отказ на уровне соединения, до HTTP дело не дошло. Идите по слоям выше.
Частая причина — API привязан к `127.0.0.1`, а не к адресу в тоннеле:
из контейнера панели это выглядит как `Connection refused`.

### Панель открывается, но без вёрстки / очень долго

Сначала измерьте, где время. **С сервера панели**, минуя туннель:

```bash
curl -sk -o /dev/null -w 'ttfb=%{time_starttransfer}s\n' https://127.0.0.1:8443/auth/login
```

Если TTFB в районе 50 мс — сервер здоров, тормозит канал. Включите `http2 on`
(см. [3.2](#32-правки-до-первого-запуска)) и поднимайте туннель со сжатием:

```bash
ssh -C -o ControlMaster=auto -o ControlPersist=60 -N -L 8443:127.0.0.1:8443 root@<IP>
```

Проверять наличие CSS так:

```bash
curl -sk https://127.0.0.1:8443/auth/login | grep -o '/_next/static/[^"]*\.css'
```

Next 16 с Turbopack кладёт стили в `/_next/static/chunks/`, а не в `/_next/static/css/`
как webpack-сборки. Сжатие Next включает сам, `gzip on` в nginx не нужен.

### Вход не проходит

Сначала посмотрите, доходило ли дело до проверки пароля:

```bash
docker exec db-amnezia-panel sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select \"createdAt\", \"levelType\", message from \"Logs\" order by \"createdAt\" desc limit 10;"'
```

- **Нет записи `Authorize success`** — не найден пользователь или не подошёл пароль.
  Проверьте фактический логин в таблице `Admins`: после `reset-root.sh` он
  `root_reseted`, а не `root`.
- **Запись есть, но выкидывает на форму** — ломается сессия. Проверьте
  `docker exec app-amnezia-panel printenv NEXTAUTH_URL` и совпадение с адресной строкой.
- **POST вообще не доходит** (`status: 0` в HAR, `ECONNRESET` в логах) — это
  `client_body_timeout 0`, см. [3.2](#32-правки-до-первого-запуска).

Проверить весь флоу без браузера:

```bash
cd /tmp && rm -f cj.txt
CSRF=$(curl -sk --http2 -c cj.txt https://127.0.0.1:8443/api/auth/csrf \
       | grep -o '"csrfToken":"[^"]*"' | cut -d'"' -f4)
curl -sk --http2 -b cj.txt -c cj.txt -X POST \
  https://127.0.0.1:8443/api/auth/callback/credentials \
  -d "login=root&password=rootadmin&csrfToken=$CSRF&json=true&redirect=false" \
  -w '\ncode=%{http_code}\n'
```

`code=200` — авторизация работает. Сравните с `--http1.1`, чтобы отделить
проблемы HTTP/2 от всего остального.

## Грабли проекта

Вещи, которые работают «как задумано», но выглядят как поломка.

**API-ключи отдаются в браузер открытым текстом.** Эндпоинт `servers.getServersTable`
расшифровывает `apiKey` и кладёт в JSON-ответ. Шифрование в базе через
`ENCRYPTION_KEY` этим сводится на нет. Если снимали HAR или показывали кому-то
экран — считайте ключи скомпрометированными и меняйте.

**Кнопка «перевыпустить» не работает на конфигах, созданных вне панели.**
`reissueConfig` начинается с поиска локальной строки и без неё бросает
`Config not found`. Такие конфиги надо **пересоздавать**: создать новый через
панель → отправить клиенту → дождаться подтверждения, что подключился → удалить старый.

**Ключи старых конфигов невосстановимы.** API отдаёт ключ único в момент создания,
в списке пиров его нет. Тихой миграции не выйдет — каждому придётся один раз
переставить конфиг.

**Кэш серверов живёт 10 минут.** Реквизиты сервера (ip, порт, ключ) кэшируются
в памяти. Кэш сбрасывается при сохранении формы сервера, но **не** при смене ключа
на самой машине. Поменяли ключ на сервере — обязательно пересохраните форму в панели.

**Healthcheck у сервиса `app` скопирован от базы.** В `docker-compose.yaml` стоит
`pg_isready`, которого в node-контейнере нет, — `docker ps` вечно показывает панель
как `unhealthy`. Ни на что не влияет, можно просто удалить блок.

**Миграций Prisma в репозитории нет.** `start.sh` вызывает `migrate deploy`
(тот пишет `No migration found`) и следом `db push`, который и приводит схему
в порядок. Так задумано, это не ошибка.

**`yarn lint` не работает.** `next lint` удалён в Next 16, а прямой запуск eslint
падает на `Converting circular structure to JSON`. Реальные гейты —
`tsc --noEmit` и `yarn build`.

**AmneziaWG 2.0 и 3.x — один протокол для API.** Оба используют значение
`amneziawg2` и контейнер `amnezia-awg2`; версия определяется автоматически по
содержимому `awg0.conf` и попадает в поле `protocol_version` внутри `vpn://`-конфига.
Отдельного значения в `Protocols` заводить не нужно — если слать `amneziawg31`,
создание конфигов сломается.

Проверить, какая версия на сервере:

```bash
docker exec amnezia-awg2 grep -iE \
  'HeaderProtectionKey|ContentPaddingAddition|RekeyAfterTime|RekeyTimeout|RejectAfterTime|KeepaliveTimeout|MaxHandshakeAttempts|RandomTrailers|DisableCookies' \
  /opt/amnezia/awg/awg0.conf
```

Пусто — 2.0. Есть строки — 3.x, и тогда официальный образ API будет выдавать
клиентам неполные конфиги: он не перекладывает эти параметры и всегда проставляет
`protocol_version: "2"`. В этом случае нужен форк с поддержкой 3.x, **на всех
серверах сразу** — расхождение версий API между машинами отлаживается дорого.

> Утверждение «конфиги 2.0 перестанут работать против 3.x-сервера» —
> вывод из кода детекции, а не проверенный факт. Перед массовым перевыпуском
> проверьте на одном устройстве.
